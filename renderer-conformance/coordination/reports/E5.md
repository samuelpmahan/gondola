# E5 — Four-actor renderer conformance

## Scope

The additive checker uses four isolated Chromium pages: one Go collection runtime initially mounted with `dom`, one with `react`, one with `godom`, and an independent original React 19.3.1 reference. Every fixed and seeded action script runs in each page. Candidate hosts are admitted from descriptors built from the Go-generated manifest; the React reference does not supply candidate snapshots.

Every tick compares state, tree, bindings, messages, audit records, transport events, server requests, pending requests, raw HTML and renderer snapshots, control state, live properties, and candidate-to-reference plus candidate-to-candidate parity. Focus and selection comparisons begin after an explicit focus action and continue through subsequent ticks. The Go contract CLI validates every candidate snapshot observation, caching only byte-identical JSON snapshots after all browser channels have been compared.

The native `CompareInteraction` gate runs separately for `dom`, `react`, and `godom` against the independent reference for every scenario. The adversarial set covers retained input identity through same-backend reorder and HTTP completion on all three renderers, all six directed backend swaps with physical node replacement and logical focus/selection restoration, GoDOM detached callbacks, disabled controls, stale path/key rejection, path reuse, invalid Go bridge calls, and metadata version/capability rejection before runtime initialization, renderer mount, or transport calls.

## XR-E5 fail-closed repair

The independent XR-E5 review found synchronized omissions in seven observation channels, missing explicit-focus witnesses, an unchanged `add` accepted without evidence that Go dispatch ran, and native frames that could be blank across all actors. The checker now validates the required observation shape for all four actors before parity comparisons. A focus action requires each actor to report the requested logical key and range, with start/end clamped to the pre-action controlled `Draft`'s JavaScript string length (UTF-16 code units). Requested selection direction is asserted only for noncollapsed ranges when the action explicitly requests `forward` or `backward`; `none` leaves the browser policy unspecified. Actual focus directions are still compared across actors for every noncollapsed range, and collapsed ranges ignore direction in parity. For registered `add`, `reset`, `click`, and `fill` actions, the checker resolves the handler from the pre-action tree/bindings and enabled state, checks the expected event message in every actor, and requires the three candidate Go dispatch counters plus their per-action receipts to match the expected delivery count. A disabled native target must report zero dispatches. The independent React reference is checked through the shared expected-message trace rather than relying on its counter implementation. Direct raw dispatches go through the counted runtime API. Expected text-input fill messages remove only CR and LF, matching `input[type=text]` sanitization while preserving all other whitespace.

Before invoking `CompareInteraction`, the checker now verifies every native frame for all four actors against the same indexed browser tick: the state/tree/bindings/messages and HTTP/audit JSON must be present and match, the native DOM and live input value must match, and the step tuple must equal the tuple resolved from that script action. Missing, malformed, blank, or cross-tick native data skips the comparator and records a failure.

## Boundaries

This run exercises the existing collection, renderers, and HTTP loopback lab in Chromium with four isolated actor pages. Focus behavior is asserted only after explicit focus/selection actions. It does not claim pixel equivalence, IME behavior, other browser engines, concurrent browser scheduling, or production-service behavior.
