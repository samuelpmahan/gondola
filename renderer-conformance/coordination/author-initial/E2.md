# E2 — Go/WASM keyed DOM renderer

Implemented a direct `syscall/js` renderer in `godom` and the singleton
`gobiGoDOM` bridge in `cmd/godom-wasm`. It consumes only the Go-owned
`rendercontract.ParseSnapshot`/`ValidateSnapshot` profile and does not import
the collection package or implement application transitions. Bridge methods
are `mount`, `update`, `snapshot`, `domSnapshot`, `click`, `focusState`,
`restoreFocus`, and `unmount`; failures are returned as one-field
`{error: string}` objects.

Keyed elements are reused by key and tag across sibling reorder. Text nodes
retain child-index identity within a retained parent. The implementation
patches the actual DOM, orders input attributes as ordinary attributes then
`type` and `value`, only assigns controlled `.value` when the snapshot value
changes, and routes current event paths/keys through the facade. It removes and
releases callbacks when events/elements disappear or on unmount. Focus capture
and restoration use the logical input key, selection range, and selection
direction.

## Browser spike gate

Before full renderer work, two independent Go 1.24 WASM runtimes passed the
minimal Chromium spike in `cmd/godom-wasm/spike-mini`. The renderer's exported
Go `click` calls the native DOM element's `.click()`, enters a renderer Go
callback, calls the JavaScript facade, enters the app Go dispatch, then
synchronously re-enters the renderer Go `update`. Exact Go sources, HTML,
Node runner, and reproduction command are retained in that directory.

Observed result from the minimal mechanism probe:

```text
SPIKE_RESULT updated:1:1 updated:1:1
```

This mechanism-only probe used a small Go app. Separately, the final smoke
below passed with `cmd/collection-wasm` as the app runtime and `cmd/godom-wasm`
as the renderer runtime.

## Red-path checks

The browser smoke command below also asserts these deliberately rejected
operations while checking the resulting DOM and renderer state:

- `gobiGoDOM.snapshot("extra")` returns exactly an error object for wrong
  arity. The smoke checks wrong arity for all eight public methods and checks
  that each return object has only the `error` field.
- An unknown snapshot field returns an error before changing `root.innerHTML`.
- A text-node child path cannot be clicked as an element.
- A facade dispatch returning a malformed snapshot fences the renderer and
  calls `facade.rendererFailed`.
- A detached removed-row button has no remaining listener and cannot mutate
  the Go app.

All these negative-path assertions passed in Chromium.

Actual Go/WASM browser smoke:

```sh
CHROMIUM_EXECUTABLE_PATH=/tmp/chromium \
  /tmp/gondola-node22/node_modules/node/bin/node \
  cmd/godom-wasm/smoke.mjs \
  /tmp/godom.wasm /tmp/collection.wasm \
```

Observed output:

```json
{"ok":true,"rowsAfterReorder":[2,1],"retainedInputKeys":["row-1-input","row-2-input"],"focus":{"key":"row-2-input","selectionStart":2,"selectionEnd":7,"selectionDirection":"backward"},"completionSaved":"saved two","detachedCallbackCleaned":true,"wrongArityRejectedForAllMethods":true,"invalidSnapshotDidNotMutate":true,"callbackFailureNotified":true}
```

The real app smoke exercised the renderer's exported click through native DOM
`.click()` into a renderer Go callback, JavaScript facade, and the independent
Go collection WASM dispatch; Go then applied the returned snapshot. It added
two rows, changed both controlled inputs, reordered row 2 while preserving the
same input object and backward selection, saved and directly completed a Go
collection request, retained input identity/focus across that update, removed
a row and verified its detached listener no longer dispatched, and checked
failure notification and invalid-snapshot behavior. It also rendered a
generic v1 snapshot containing an empty text node and adjacent text nodes,
checked the physical `childNodes` and verified that the following button still
dispatches at the current path `3`.

The actual completion check calls `gobiCollection.complete` and
`gobiGoDOM.update` directly; it does not claim HTTP transport coverage. The
full conformance harness owns HTTP/effect comparison. This profile excludes
fragments, styles, arbitrary components, IME behavior, hydration, pixel
equivalence, and production service behavior as specified in `PLAN.md`. The
cross-backend conformance replay is owned by E5/root and is not claimed as an
E2-only result here.
