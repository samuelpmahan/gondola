# E4 — app-independent contract fixtures and renderer schedules

## Delivered

- `cmd/conformance-fixtures` emits one Go-generated `{manifest, fixtures}` JSON bundle. It constructs snapshots with `gobi.Node`, `inputbinding.Binding`, `gobi.Message`, and `rendercontract.DefaultManifest`, then checks each intended outcome with `rendercontract.ParseSnapshot` before writing the bundle.
- The 32 fixtures include 7 valid snapshots (controlled input with HTML-sensitive text and disabled controls, keyed sibling views, root text, empty text, adjacent text, exact depth 64, and exact node count 4096) plus 25 rejected cases covering exact envelope schema, nulls, bindings, keys, kinds/styles/fragments, depth 65, and node count 4097.
- Three malformed/duplicate/trailing JSON inputs are explicitly `raw-json-only`: the native parser rejects their source bytes, while the JS checker does not pretend a browser object can preserve that syntax distinction.
- Valid fixture records include `expectedHTML` from the existing Go `gobi.HTML` renderer. The Chromium page parses that string through a `<template>` before comparing it to live DOM serialization.
- `fixture-check.mjs` compares the Go CLI and `validateSnapshotAgainstManifest` for every parseable snapshot. `fixture-check.browser.mjs` serves the page on the existing loopback HTTP lab and renders each positive fixture through DOM, React, and Go DOM. Invalid browser-object fixtures are rejected at the manifest admission boundary before renderer updates; the test confirms each candidate's DOM and snapshot remain unchanged.
- `renderer-conformance/scripts.mjs` layers renderer coverage over the unmodified keyed-editor schedule module. It adds all six directed backend transitions across `dom`, `react`, and `godom`, adds Go DOM to the focused reorder/focus script, and injects a bounded Go DOM actor transition into generated schedules without changing the action schema.

## Limits

The browser fixture source is deliberately a static snapshot facade with no collection transitions; it verifies renderer contract compatibility and does not stand in for the actual Go application runtime. The full replay remains responsible for application state, events, HTTP completion, focus handoff, and the unchanged independent React reference. Browser object checks cover parsed JSON objects; duplicate-key, malformed, and trailing-byte cases are native-parser-only because parsing loses their raw-source distinction. HTML comparison is bounded to the Go-generated v1 fixtures and uses the Go static renderer plus browser template serialization as the reference, not a candidate renderer as oracle.
