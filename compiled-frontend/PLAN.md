# Execution and acceptance plan

The interactive counter is already implemented and independently executed in PR1. PR2–PR10 extend replaceable renderers, controlled values, effects, keyed reconciliation, independent roots, nested lifetimes and typed parent/child communication. Current work stacks on the exact accepted PR10 application tree. Its composed outcome is a bounded staged compiler, rather than another handwritten application adapter.

1. Prove the pinned public GoScript compiler and actual value/struct/slice/float ABI. Preserve negative evidence, including integer-overflow limitations and the raw exported counter's mutable-call boundary.
2. Publish closed Go contracts and source-located, conservative supported-profile analysis. Compile Go forwarding functions so Go retains responsibility for value-copy application calls. Generate encoders from Go types.
3. Use one generic React backend and runtime for the unchanged counter, controlled form/checkbox, keyed list, and deterministic effect. Preserve literal event arguments and separate explicit bindings.
4. Replay the same four deterministic fixture scripts through native Go, direct emitted JavaScript independent of the runtime, and mounted React. Compare every requested action, actual message, dispatch identity, exact typed state, tree, bindings, effect correlation/order and independent mounted DOM expectations. Reject deliberately corrupted evidence.
5. Independently review and repair boundary failures before acceptance. Preserve initial amendments and failed executions. Gate positive evidence on frozen sources and before/after hashes.
6. Run the complete inherited Go1.24 static/interaction entrypoint, then the isolated Go1.27.3 compiler suite and Node22/Chromium conformance. Build and exercise a visible four-app demonstration. Record exact commands, versions, fixture inputs, hashes and limits.
7. Publish a scoped feature branch and draft review PR stacked on PR10. Verify the published tree and fresh CI. Do not merge main or deploy.

Native Rebalancer1.0.4 assigns six real Luna6 XHigh sessions, the maximum six available child slots. Solver allocation and platform dispatch are separate records. Resumed sessions are attributed explicitly; historical completed/amended receipts are never overwritten as pristine passes. New repair and audit packets have disjoint ownership and independent acceptance gates.

The default command is `bash run-compiled-frontend.sh`. `bash run-compiled-frontend.sh --compiled-only` is an explicitly partial rerun of the compiler gates, for use after dependencies and inherited gates have been executed separately. It cannot establish a fresh inherited regression pass.
