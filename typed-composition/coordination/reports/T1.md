# T1 — Go typed composition manager

## Result

Implemented `composition.Manager` as a serialized wrapper around a private `multisession.Manager`. It adds direct child inputs with safe monotonic revisions, typed immutable publication receipts, per-session message ordering, read-only view policy, and sorted dirty-ID draining. The wrapped manager is not exposed. No browser or end-to-end integration pass is claimed here.

## Implementation

- Added the Go API described in `typed-composition/DESIGN.md`: `Inputs`, `Publication`, `State`, `Snapshot`, and `Manager` methods for creation, snapshots, dispatch, completion, effects, audit, disposal, inputs, publication, and dirty IDs.
- Inputs accept valid UTF-8 titles up to 256 bytes. Only a live immediate parent can update its child. Equal accepted values still increment the child revision; root inputs remain at revision zero. Revision exhaustion and failed validation or identity checks leave state unchanged.
- Publication captures the child's live row `Saved` value and save count, requires the current input revision and a writable non-root child, and adds a manager-global safe sequence to the immediate parent's inbox. Repeated calls create distinct receipts. Parent inbox history survives child disposal, while disposing an inbox owner removes that inbox; the global sequence is retained.
- The composition view preserves collection positions 0–2, adds title and inbox paragraphs at 3–4, and appends each row's publish button at index 9. Read-only mode disables every input and button while preserving declared handlers and bindings. Disabled events are checked for canonical path, key, and event before suppression. A publish dispatch also requires `Step.Value` to equal the current literal `ROW/REVISION` handler argument.
- Base and composition messages share one per-session ordered history. Successful edits, completions, input updates, and publications mark the expected live IDs dirty. Snapshots copy collection rows, inboxes, messages, bindings, and generated trees; `Changes` returns sorted unique live IDs and a fresh nonnil slice.
- During author review, an invalid `Complete` reply was found to return the current snapshot while dropping the original error. The implementation now returns both the snapshot and error, with regression coverage for reply ID 0 and an unsafe ID.

## Limitations

This report covers the Go package and its native tests. It does not claim the WASM bridge, browser replay, renderer propagation, inherited session-tree runner, or demo passes. Parent checks enforce structural API rules; they do not authenticate a parent as a production security principal or guarantee transport delivery. No rollback is claimed if a later renderer refresh fails after a Go transition commits.
