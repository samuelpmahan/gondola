# T4 — Independent composition model and replay scripts

## Result

Implemented an independent JavaScript composition manager over the existing session-tree and collection references. It models typed inputs, direct-parent publication, revisions, immutable receipts, ordered child messages, inbox retention, read-only projection and dispatch policy, and dirty-ID draining. The model does not import or execute candidate Go transition code.

The composition snapshot retains the collection state/tree/bindings/messages shape, then adds Inputs, InputRevision, and Inbox; the generated tree keeps the original collection positions and appends the typed title, inbox count, and per-row publish control. mountCompositionReferenceCollection aliases the existing pinned React 19.3.1 projection.

## Scripts

scripts.mjs exports three fixed public-API scenarios and deterministic seeded scenarios using the exact native {method,args} action shape. Defaults are 30 cases per seed, seeds 20261030 and 20261031, and a 40-action maximum per generated case.

The fixed scenarios cover title and inbox visibility, disabled root/empty publish controls, equal input revision increments, stale revisions, captured saved values after later draft edits, rendered publish dispatch, read-only controls with a pending completion, direct-parent grandchild routing, child inbox retention after deletion, owner disposal, and fresh IDs on recreation. runReferenceScript emits per-action frames in the native replay format and drains dirty IDs after each operation.
