# T3 host implementation report

**Outcome: mixed_change.** Implemented the typed composition host and additive refresh APIs across the existing keyed, multi-root, and session-tree hosts.

## Host behavior

- `createKeyedHost().refresh()` reads `runtime.snapshot()`, validates and caches the snapshot, updates the current renderer in place, and queues its effects. It never calls `init()`. The existing keyed DOM and React renderer updates preserve focus and selection.
- Added the generation-fenced `snapshot()` method to `createSessionRuntime()`, then exposed `refresh(root)` from the multi-root host and `refresh(id)` from the session-tree host. Each method rejects inactive targets and reports renderer update failures.
- `createCompositionHost({manager, descriptors, transportFactory})` wraps the exact lower-case composition bridge and the existing `createSessionTreeHost()`. Its public surface is the session-tree API plus `setChildInputs(parent, child, inputs)` and `publish(child, row, revision)`.
- Successful manager transitions and typed mutations schedule one microtask after the current call stack. The host drains Go `changes()`, validates sorted unique safe IDs, filters IDs absent from the current Go tree, refreshes each live changed session in place, and repeats until the manager reports no more changes. Successful typed calls return cloned Go results.
- `settled()` waits for existing renderer/effect work, composition refresh propagation, and effects triggered by refreshed snapshots. Go policy errors and exact error frames are surfaced without scheduling a refresh. Rendering failures reject settled work; committed Go state is left intact.
- An underlying manager object is reserved to one composition host.
