## Contracts

New package `composition` wraps `multisession.Manager` under its own mutex. It never exposes the wrapped manager. Existing packages and signed receipts stay intact except three additive generic host refresh methods.

Go API: `NewManager() *Manager`; `Create() (multisession.SessionID,error)`; `CreateChild(parent) (SessionID,error)`; Tree/List/Effects/Audit/Dispose/DisposeTree retain multisession signatures; Snapshot/Dispatch/Complete return composition.Snapshot. New `SetChildInputs(parent,child SessionID, inputs Inputs) (Snapshot,error)`, `Publish(child SessionID,row collection.RowID,revision uint64) (Publication,error)`, `Changes() []SessionID` (drains sorted unique changed live IDs).

`Inputs {Title string; ReadOnly bool}`: default empty/false; Title at most 256 UTF-8 bytes, valid UTF-8. Only a live immediate parent may set its child's inputs. Each accepted call increments that child's InputRevision, including equal values. Failed validation/identity/revision exhaustion leaves everything unchanged. It is a direct input, not transitive inheritance. Root input revision is zero. Safe integer limits apply to every externally visible ID/revision/sequence.

`Publication {Sequence uint64; ParentID SessionID; ChildID SessionID; RowID collection.RowID; Saved string; Saves int; InputRevision uint64}`: Publish accepts only a live non-root child, existing row with nonempty Saved, and exactly current InputRevision. It captures Go state, never caller-supplied content. Each accepted publish increments one manager-global monotonic sequence and appends an immutable receipt to the immediate parent's Inbox. Repeated publishes are distinct ordered messages. Parent inbox history survives child deletion/disposal; disposing its owner deletes that inbox. Sequence is not reused after disposal. A grandchild publishes only to its direct parent. ReadOnly suppresses publication too. No shared transaction/transport message delivery guarantee is claimed.

`State` embeds collection.State and adds `Inputs Inputs`, `InputRevision uint64`, `Inbox []Publication`; Snapshot has exactly state/tree/bindings/messages. Collection state remains Go-owned. Snapshot defensive copies all mutable data. View retains original collection child positions 0(Add),1(Reset),2(rows). Appends `p` key composition-title at3 (text `Title: ` + Title), `p` key composition-inbox at4 (text `Published: ` + len(Inbox)), and one final per-row button at child index9 with key row-ID-publish, class publish, label Publish, click handler name publish and Arg `ROW/REVISION`. Publish disabled for roots, empty Saved, or ReadOnly. Title and inbox are visible in all backends. In ReadOnly every button AND input carries disabled; existing handlers/bindings remain declared. Disabled Step validation still checks canonical path/key/event before suppression. Complete still accepts pending replies while ReadOnly; policy does not cancel requests.

Dispatch intercepts only row publish controls; validates the current Gobi view, canonical path/key/event and exact literal revision argument, then calls typed publish internally. The publish Step.Value must equal the current declared ROW/REVISION literal, including when disabled; renderers already send literal handler arguments. Other collection Steps delegate to the wrapped manager after readonly gating. Successful publication adds gobi.Message{Name:publish,Arg:ROW/REV} to that child's snapshot message history in correct order with base messages. Errors do not append messages, consume sequence, or dirty IDs. Successful edits/completions dirty target; SetChildInputs dirties child; Publish dirties child+parent. Changes returns nonnil defensive sorted unique live IDs; disposal removes dead dirty IDs. Arbitrary JS is not a security principal: parent checks enforce API structure, not authentication.

## Browser seam

New global gobiComposition exposes exact-arity create/createChild/tree/list/snapshot/dispatch/effects/complete/audit/dispose/disposeTree/setChildInputs/publish/changes and existing encodeHTTP/decodeHTTP. Strict primitive safe IDs, closed JSON schemas, exact property types and no unknown fields. WASM is real Go application execution. New native replay command consumes JSON actions and returns full frames for independent browser/native comparison.

Add `refresh()` to keyed host, `refresh(root)` to multi-root host, `refresh(id)` to session-tree host. Add generation-guarded `snapshot()` to createSessionRuntime in multi-root/runtime.mjs. Refresh fetches runtime.snapshot, validates, updates cached snapshot and existing renderer without reinitialization, then drains effects. It preserves observed focus/selection through normal keyed renderer update behavior. Existing APIs unchanged.

`createCompositionHost({manager,descriptors,transportFactory})` wraps createSessionTreeHost and only coordinates lifecycle and dirty refresh. It exposes tree host methods plus setChildInputs(parent,child,Inputs) and publish(child,row,revision). Input argument records reach the strict Go boundary without host cloning or coercion: cloning before admission can execute accessors and erase unknown own fields. The WASM boundary admits own data-property values and fences nested API calls during validation; this is a structural contract, not authentication or a JavaScript sandbox. Wrap manager mutators to schedule a microtask: drain Go Changes, refresh live IDs after current dispatch returns, repeat until quiescent, fence disposed IDs; settled awaits this propagation and inherited effect queue. Rendering failures are surfaced; no rollback of committed Go state is claimed. Exclusive manager ownership is required. No JS application state transitions. Inputs and publication do not remount other sessions. Existing renderer handles are reused.
