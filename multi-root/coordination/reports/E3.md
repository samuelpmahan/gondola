# E3 — Multi-instance GoDOM bridge

## Delivered

- `cmd/godom-wasm/main_wasm.go` now publishes `gobiGoDOM.mount(root, facade) -> rendererAPI`. The global object contains only `mount`; each returned API closes over its own `godom.Renderer` and has independent `update`, `snapshot`, `domSnapshot`, `click`, `focusState`, `restoreFocus`, and `unmount` methods.
- Each handle tracks its own mounted state. Unmount is idempotent. Other calls on an unmounted handle return `{error: string}`; those stale calls cannot reach another renderer. Existing renderer error fencing and `rendererFailed` notification stay on the renderer's own facade.
- `renderer-conformance/adapter.mjs` adapts the returned renderer API. It also retains a bounded legacy path only when a bridge has the complete published singleton method table and `mount` returns null/undefined, covering prior singleton test doubles. Mount errors and renderer-method errors remain unwrapped into adapter exceptions.
- `renderer-conformance/adapter.test.mjs` covers the instance method table, two distinct handles, stale/error results, the legacy test-double path, malformed handles, and bridge loading.
- `cmd/godom-wasm/smoke.html` now runs two actual GoDOM instances in separate roots simultaneously. Root A retains the existing Go collection behavior; root B uses a separate facade. The browser smoke checks independent snapshots, DOM snapshots, updates, click dispatch, focus capture/restore, error fences, idempotent unmount, stale handles, and reuse of a vacated root.

## Limits

- The two-renderer smoke exercises GoDOM with two live WASM renderer handles and separate roots. Only root A is backed by the existing collection WASM bridge; root B uses an independent JS facade fixture, so this packet does not claim multi-session collection coverage.
- Browser verification used the pinned local Chromium only. Other browser engines, sustained high-churn mount/unmount memory behavior, and the integrated multi-root runner remain outside this packet's gates.
- Build outputs were written under ignored `build/` directories for these checks; no Git commit or branch operation was performed.
