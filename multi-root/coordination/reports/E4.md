# E4 — JavaScript multi-root host and runtime

## Delivered

- `multi-root/host.mjs` exports `createMultiRootHost({ manager, descriptors, transportFactory })`. It allocates one numeric session ID and keyed host per mounted DOM root, requires a fresh transport for every root generation, and rejects reused session IDs or transport objects before they can alias another owner.
- `multi-root/runtime.mjs` exports `createSessionRuntime(manager, sessionID, isCurrent)`. It scopes `init`, `dispatch`, `complete`, `effects`, and `audit` calls to one session, clones bridge results, and fences calls after the root generation retires. It contains no application transition logic.
- Root teardown first retires the generation and removes it from the active root map, then disposes only that Go session, routes returned cancel commands through that root's idempotent transport wrapper, and unmounts its keyed host. Callback delivery checks both record identity and generation before entering the keyed host.
- Renderer swaps delegate to the existing keyed host, preserving that root's focus behavior and rollback semantics. `snapshotAll()` reports each active root's session ID, generation, backend, snapshot, audit, DOM snapshot, focus, lifecycle, and root-local errors.
- `multi-root/host.test.mjs` uses strict manager, renderer, and transport fakes to cover local request ID collisions, scoped cancellation, late replies, unmount before effect draining, root reuse, focus-preserving swaps, failed replacement rollback, root-local renderer failure, duplicate session IDs, and transport reuse.
- `multi-root/runtime.test.mjs` checks session-scoped bridge calls, output mutation isolation, stale-generation fencing, invalid IDs, and incomplete bridge rejection. The mutation probe changes returned snapshot/effect/audit values and confirms those changes do not reach fake manager state.

## Verification

Toolchain: Node `v22.23.4`.

```sh
/tmp/gondola-node22/node_modules/node/bin/node --version
# v22.23.4

/tmp/gondola-node22/node_modules/node/bin/node --test multi-root/runtime.test.mjs multi-root/host.test.mjs
# 12 tests passed, 0 failed
```

Negative controls in that test command passed: duplicate session IDs cannot create an alias or dispose the existing owner; the same transport object cannot serve two live roots or a later generation; late deliveries after disposal do not reach the manager; and a queued request is canceled without draining its effects after immediate unmount. Strict fakes match the declared `gobiMultiRoot` methods (`create`, `snapshot`, `dispatch`, `effects`, `complete`, `audit`, `dispose`, `list`) and the per-mount renderer API accepted by the existing keyed host.

## Limits

- E4's focused tests use deterministic JavaScript fakes for the Go manager bridge, renderers, and transport. They exercise the real keyed host and E4 adapters, but do not launch a multi-root Go/WASM browser session or verify HTTP codec behavior.
- The browser demo and whole-project runner belong to E6. Cross-browser behavior, sustained high-churn mounts, and end-to-end three-WASM-root parity were not verified in this packet.
- No Git state, commit, or publication operation was performed.
