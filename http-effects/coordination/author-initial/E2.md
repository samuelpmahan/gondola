# E2 — fetch transport

## Result

Implemented `createHTTPTransport({runtime, url, fetchImpl = globalThis.fetch})` in `http-effects/transport.mjs`. It consumes the unchanged host's `start(command, deliver)` and `cancel(id)` calls, encodes and decodes through the Go runtime, sends same-origin `POST` requests with JSON, and fences callbacks after cancellation or disposal. Failures from encoding, URL resolution, fetch, or body reads become `{ID: expectedID, Value: "", Error: "network error"}`. Decoder exceptions and malformed decoder replies become safe `{ID: expectedID, Value: "", Error: "invalid response"}` replies.

`url` accepts the required fixed string and additionally a synchronous `(command) => string | URL` resolver so the harness/demo can route each save to a selected lab lane/mode without changing host or Go commands. `settled()` waits for the transport's request/decode/delivery work only. Unexpected work or delivery-callback failures are retained even if the fetch finishes before `settled()` is called; one `settled()` call consumes and reports each retained failure exactly once. `dispose()` is idempotent, logs cancellation for pending requests in start order, aborts them when possible, and suppresses late callbacks.

Normalized log entries are exactly:

```js
{ Kind: "start", ID, Value }
{ Kind: "cancel", ID }
{ Kind: "reply", ID, Value, Error }
```

## Limits

- This report covers the transport module and scoped tests only; it does not certify the Go lab, Chromium replay, complete harness, demo, workflow, or inherited regression suite.
- Abort remains advisory. A fetch implementation that ignores abort keeps `settled()` pending until its work resolves, while delivery remains fenced.
- The unchanged host has no transport-claim hook; callers must create a distinct transport instance for each host.
