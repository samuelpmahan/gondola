# E6 report: loopback HTTP laboratory server

## Scope

Added `httplab.Server` and `cmd/http-lab`. The server serves static files from `-root`, reserves `/api/`, and accepts strict `{ID,Value}` JSON with positive safe integer IDs. It supports success, server-error, wrong-ID, malformed-body, HTTP 503, socket-drop, and held-response modes. The `drop` mode flushes an HTTP 200 response header with `Content-Length: 128`, writes only a short JSON prefix, and closes the socket. This makes body consumption fail after headers have established a response, avoiding the Chromium POST replay observed with an abrupt close before headers.

The control API is:

- `POST /api/save?lane=NAME&mode=MODE` (mode defaults to `success`). A held request stays open until release. Duplicate `(lane, ID)` requests receive 409; the original retained record is unchanged.
- `POST /api/release?lane=NAME&id=N[&mode=success]` (release mode defaults to `success`). It accepts one release while the request is held. Unknown IDs return 404; repeated, completed, or canceled releases return 409 without changing the original record.
- `GET /api/requests?lane=NAME` returns `{"lane":"NAME","requests":[...]}`. Records are sorted by ID and include `Lane`, `ID`, `Value`, `Mode`, `ResultMode`, `State`, `CancelObserved`, `Status`, `ResponseID`, and `Error`. `State` can be `processing`, `held`, `completed`, `cancelled`, or `dropped`.

The command defaults to loopback `127.0.0.1:0`, rejects non-loopback bind addresses, and prints a single readiness line, for example `{"url":"http://127.0.0.1:43383"}`. It defaults `-root` to `.`.

## Chromium drop follow-up

E4's reproducible direct Chromium probe passed against the freshly rebuilt `http-effects/build/http-lab` binary with:

```sh
CHROMIUM_EXECUTABLE_PATH=/tmp/chromium /tmp/gondola-node22/node_modules/node/bin/node http-effects/harness-drop-probe.mjs --output http-effects/build/e4-drop-chromium-probe-reproduced.json
```

Evidence is retained at `http-effects/build/e4-drop-chromium-probe-reproduced.json` (browser version `153.0.8010.0`). Chromium received HTTP 200 headers, then `response.text()` rejected with `TypeError: Failed to fetch` (`net::ERR_CONTENT_LENGTH_MISMATCH`). The browser made one POST only; it did not retry into the duplicate-ID 409. `/api/requests` showed exactly one record with `State:"dropped"`, `Status:200`, and `CancelObserved:false`.

This is a finite, loopback laboratory server, not a production service. An aborted held fetch closes its original request; a later release cannot deliver a response through that closed socket and is rejected with 409. Cancellation records are retained in memory for the server process lifetime. The targeted Go gates above pass after the partial-body drop change; full repository/inherited Go verification is run by the coordinator separately.
