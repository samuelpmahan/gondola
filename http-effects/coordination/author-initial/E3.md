# E3 — Independent HTTP reference and action scripts

## Files

- `http-effects/reference.mjs`
- `http-effects/reference.test.mjs`
- `http-effects/scripts.mjs`
- `http-effects/scripts.test.mjs`

The reference module reuses the existing independent async-save oracle from the built React bundle, then supplies its own HTTP request encoder and strict response decoder. `createHTTPReferenceRuntime()` exposes the unchanged model methods (`init`, `dispatch`, `complete`, `effects`, `audit`, `snapshot`) plus `encodeHTTP` and `decodeHTTP`. `mountHTTPReference(container)` wraps the existing independent React oracle with those codec methods.

`makeScripts({seeds, cases, maxActions})` returns the fixed HTTP fixtures followed by reproducible seeded scripts. Actions keep the async fixture shape for `fill`, `type`, `click`, `swap`, and `stale-input`; HTTP-specific actions are `{kind:"mode",mode}` and `{kind:"release",id,mode,expectedStatus}`. Modes are `success`, `error`, `wrong-id`, `malformed`, `status`, `drop`, and `held`. A live held release expects 202; a release after cancellation, reset, or replacement expects 409.

## Findings and limits

An early independent probe found that JavaScript `JSON.parse` preserves an escaped lone surrogate while Go's standard JSON decoder replaces it. E1 subsequently made the Go wire decoder reject unpaired surrogate escapes as invalid response data; the reference now follows that stricter contract. A raw lone surrogate already present in a JavaScript body string is normalized to U+FFFD to model browser text decoding; actual invalid UTF-8 byte behavior is outside this string-based reference API.

The scripts define the harness actions but this E3 gate did not run browser/HTTP replay. E4 owns the actual loopback-server replay and event checks. A canceled fetch cannot deliver a later HTTP body; canceled held records are checked through the laboratory's 409 release response, while injected fetch races and Go late-reply fencing are separate gates.
