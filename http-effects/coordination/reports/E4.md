# E4 — Real HTTP and browser comparison harness

## Files

- `http-effects/check.mjs`
- `http-effects/check.test.mjs`
- `http-effects/harness.html`
- `http-effects/harness.mjs`
- `http-effects/harness-drop-probe.mjs`
- `http-effects/coordination/reports/E4.md`

The harness reuses the unchanged `async-effects/host.mjs`, `controlled-input/dom.mjs`, and pinned React renderer bundle. It mounts two separate `gobiHTTPSave` Go WASM runtimes: one with the DOM renderer and one with the React renderer. The third participant is `mountHTTPReference`, the independently authored pinned React model and JavaScript HTTP codec. Each participant uses a separate same-origin HTTP lane against the Go laboratory server.

## Execution flow

Run from the repository root:

```sh
node http-effects/check.mjs --seeds 20261030,20261031 --cases 30 --max-actions 40
```

The runner starts `http-effects/build/http-lab` (or `go run ./cmd/http-lab` if the built binary is absent), opens `http-effects/harness.html` in Chromium, and loads two isolated Go WASM runtime objects. Playwright drives actual input and button events on the DOM candidate, React candidate, and independent React reference. Each step drains the candidate hosts and reference effect outbox, waits on per-request delivery gates and `/api/requests` state, then captures the runtime snapshot, audit, transport log, server records, live DOM, input properties, and disabled controls.

Held requests wait for the server's `held` record before the next action. Live releases must return HTTP 202 and then complete the request. A request canceled by reset, cancel, or replacement must become `cancelled` with `CancelObserved:true`; an attempted late release must return 409 and leave the record unchanged. The harness treats browser errors as fatal except console diagnostics that match a scripted API URL, mode, method, and observed HTTP status exactly. It records all API responses, failed requests, expected diagnostics, and unexpected console errors.

Every tick is compared across both Go candidates and the React reference for state, tree, bindings, messages, audit, transport ordering, server records, raw HTML, input path/value/disabled state, and all disabled control properties. The native Go `CompareInteraction(..., SameDOM)` comparator is required and runs once for each Go candidate against the React reference for every script. Missing comparator output fails the gate.

## Verification

Environment: Go `go1.24.0 linux/amd64`; Node `v22.23.4`; Chromium `/tmp/chromium`.

Focused harness tests:

```sh
/tmp/gondola-node22/node_modules/node/bin/node --test http-effects/check.test.mjs
```

Result: 8 tests passed, 0 failed. Tests cover mismatch detection across runtime/DOM/network fields, live-versus-reported DOM checks, native step construction, CLI bounds, required native comparison, exact URL/status console classification, expected response counts, and the partial-body network diagnostic.

Fixed real-HTTP browser gate:

```sh
CHROMIUM_EXECUTABLE_PATH=/tmp/chromium \
  /tmp/gondola-node22/node_modules/node/bin/node http-effects/check.mjs \
  --seeds 20261030 --cases 0 --max-actions 40 \
  --output http-effects/build/e4-fixed-accepted.json
```

Result: 11 fixed scripts and 85 initial/action observations; 0 mismatches; all 22 native comparisons matched. The required coverage gate passed for HTTP success, live held release, pending renderer swap, cancel/reset/replacement cancellation, malformed response, wrong ID, HTTP 503, server error plus retry, dropped connection, and alternating save/cancel/reset. The report recorded 21 expected network diagnostics (15 canceled-release 409 responses, 3 status-mode 503 responses, and 3 mode=drop body failures), 0 unexpected console errors, 0 page errors, and 0 Go runtime errors.

The drop route has a separate reproducible browser probe:

```sh
CHROMIUM_EXECUTABLE_PATH=/tmp/chromium \
  /tmp/gondola-node22/node_modules/node/bin/node http-effects/harness-drop-probe.mjs \
  --output http-effects/build/e4-drop-chromium-probe-reproduced.json
```

Result: Chromium received HTTP 200 headers, then `response.text()` failed with a network error. It recorded one `net::ERR_CONTENT_LENGTH_MISMATCH` request failure, no duplicate 409 response, and exactly one `dropped` server record with `Status:200` and `CancelObserved:false`.

## Limits

An aborted fetch cannot deliver a later response over the canceled socket. The server's retained cancellation record and 409 late-release response verify that the request cannot be revived. E2's injected race tests cover callback fencing independently, and Go session tests cover stale/duplicate completion behavior. The browser gate covers the finite local HTTP lab in the executed Chromium build; it does not claim production service, authentication, cross-origin, focus/IME, or pixel equivalence.

The fixed-script gate is green. The coordinator is running the full seeded two-seed replay and will add its receipt separately; this report does not claim that seeded run has completed.
