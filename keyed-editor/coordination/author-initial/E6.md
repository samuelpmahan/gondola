# E6 — demo, runner, and CI handoff

## Implementation

`demo.html` and `demo.mjs` provide the real Go/WASM collection editor over the existing `http-effects/transport.mjs` and `httplab` service. The page exposes the complete Go snapshot, tree, element-key inventory, input bindings, messages, Go completion audit, HTTP events, server request records, rendered/live DOM, disabled controls, node identity counters, and logical input key/selection.

The demo keeps the last explicitly focused logical input selection when the user activates an editor action, releases a held HTTP result, or switches renderer. The host remains the owner of row transitions and request completion; the demo owns only presentation and focus restoration at these visible controls. The four-row cap comes from Go and leaves browser connection slots available for HTTP lab status and release requests.

`run-keyed-editor.sh` checks Go 1.24 and Node 22, clears inherited skip flags, runs `run-http-effects.sh` by default, builds `keyed-collection.wasm` and `wasm_exec.js`, runs the strict Go/WASM smoke, bundles the keyed React and independent React reference from the existing interaction dependencies, then runs Go tests, keyed Node tests, demo smoke, and `check.mjs`. `.github/workflows/keyed-editor.yml` installs the pinned interaction dependencies and Playwright Chromium before calling that runner. No npm dependency or lockfile changed.

## Not claimed by this report

The E6 author lane did not complete `run-keyed-editor.sh` or the full seeded `node keyed-editor/check.mjs` replay. The default runner was left intact; root orchestration owns the inherited full run, and E5 owns its fixed browser startup diagnosis before root performs the full seeded harness. A keyed check invocation was interrupted before it emitted a report when root requested that E6 stop at its author-owned gates. No pass is claimed for either broader gate here.

This smoke covers the existing loopback HTTP lab in Chromium. IME composition, other browser engines, pixel equivalence, production HTTP services, and arbitrary concurrent browser scheduling remain outside E6 verification.
