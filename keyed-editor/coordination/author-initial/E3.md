# E3 author report: keyed React renderer and update host

## Delivered

- Added `mountKeyedReact(root, runtime)`, a finite Go `Node` renderer that validates each snapshot, uses each element `Node.Key` as the actual React reconciliation key, and does not render keys as HTML attributes.
- Input and click events resolve the element's current child-index path from its logical key and dispatch exactly `{Path, Event, Value, Key}`. Input values come from `currentTarget.value`; literal click values come from the declared handler `Arg`.
- Added keyed React `update(snapshot)`, `snapshot()`, `domSnapshot()`, `click(path)`, `focusState()`, `restoreFocus(state)`, and `unmount()` methods. Updates validate and build the candidate tree before changing the accepted snapshot. Retained keyed DOM elements keep object identity; focus and selection use E2's shared key-based focus helpers.
- Added `createKeyedHost(root, runtime, renderers, transport, initialBackend = "dom")`. It leases one runtime object, calls underlying Go `init()` once, serves cached snapshots to each renderer, fences stale facades by generation, queues outbox and completion work, and retains request records for late and duplicate replies.
- Synchronous renderer events update through the renderer API. A transport completion calls `runtime.complete(reply)` and then `selectedRenderer.update(next)` on the current renderer; it does not remount. Backend replacement captures logical focus/selection, remounts from the cached snapshot, and restores that state by key. A failed replacement cleans the attempted renderer and remounts the old renderer with the captured focus state when possible.
- Added browser and host tests for keyed movement, current path/key dispatch, node identity, selection restoration, detached input suppression, focused-row removal, key-attribute absence, async completion without remount, late/duplicate reply races, runtime lease, and mount/update/replacement cleanup.

## Verification

Environment: Node `v22.23.4`, Chromium `153.0.8010.0`, React/ReactDOM `19.3.1` from the pinned interaction dependencies.

Command:

```sh
PATH=/tmp/gondola-node22/node_modules/node/bin:$PATH \
CHROMIUM_EXECUTABLE_PATH=/tmp/chromium \
node --test keyed-editor/protocol.test.mjs keyed-editor/dom.test.mjs \
  keyed-editor/react.test.mjs keyed-editor/host.test.mjs
```

Result: **18 tests passed, 0 failed**. The React test bundles React/ReactDOM with the pinned `interaction/node_modules/esbuild` into a temporary file and exercises the renderer in local Chromium. The Chromium path is explicit because Playwright's default browser cache is empty in this container.

The E3 host tests use an in-memory Go-runtime fixture and the unchanged manual async transport. They verify that save effects drain after the event callback, completion updates the same mounted renderer, duplicate/late replies remain stale, failed renderer replacement cleans up and restores the prior backend, and a disposed/failed host releases the runtime lease.

## Limits

- The browser test uses a JavaScript fixture, not the real Go/WASM session or live HTTP lab. The E5/E6 composed browser, WASM, and HTTP gate remains necessary.
- Browser behavior was exercised in Chromium `153.0.8010.0`; IME composition, other engines, pixel output, and concurrent browser scheduling were not tested.
- React updates are incremental. If a browser DOM operation throws mid-render, the renderer fences later events and the host can unmount it; this lane makes no transactional DOM rollback guarantee.
- This is the bounded Gobi node subset described by the shared protocol, not a generic React compiler or application-domain renderer.
