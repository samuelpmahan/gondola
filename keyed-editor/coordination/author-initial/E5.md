# E5 author report: browser harness and adversarial checks

## Scope and source freeze

E5 added only the browser checker, fixture, request tracker, focused unit tests, and required probe validator:

- `keyed-editor/check.mjs`, `check.test.mjs`
- `keyed-editor/harness.html`, `harness.mjs`, `harness-tracker.mjs`, `harness.test.mjs`
- `keyed-editor/adversarial.mjs`

The checker drives three isolated Chromium contexts against one existing Go HTTP lab: a Go/WASM host using the DOM renderer, a second Go/WASM host using the React renderer, and the independently modeled and rendered React reference. Each actor uses a distinct lane per scenario (`keyed-e5-<index>-<participant>`). The fetch tracker waits on individual response bodies so held requests do not block unrelated releases or state reads. ## Diagnosed attempts retained

- The first launch omitted `CHROMIUM_EXECUTABLE_PATH`; Playwright reported that its default browser executable was absent. That run did not produce a comparable trace.
- The next browser attempt stalled because the fetch tracker tested `record.done`, which held a promise and was always truthy. The parent identified the exact predicate; E5 now tracks completion with a separate `doneState`. The attempt had started before checkpoint logging was added and emitted no JSON trace. Its original output name was not reused.
- Attempt 03 completed and retained `keyed-editor/build/keyed-e5-fixed-attempt-03.json`: it exposed expected 409/503/drop API diagnostics incorrectly counted as page errors and a path-reuse probe that selected the wrong removed row. The checker now preserves API responses and request failures as separate evidence, while only application console errors fail the run; the probe removes the last row so the next ID reoccupies the same path.
- Attempt 04 is the clean fixed-scenario receipt above. The full two-seed run also passed.

## Limits

Focus assertions run only after explicit focus and selection actions; the checker does not infer focus behavior from pointer clicks or disabled controls. Runs cover serialized actions in Chromium against the loopback HTTP lab. IME composition, concurrent browser scheduling, other browser engines, pixel equivalence, and production services remain untested.
