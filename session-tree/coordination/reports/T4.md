# T4 — independent session-tree reference and schedules

## Result

Implemented the independent JavaScript manager reference, a pinned React reference projection, and bounded deterministic replay schedules. The reference maintains its own parent graph and uses the existing independent `keyed-editor/model.mjs` collection model per session. It does not import candidate host, renderer, or collection implementation code, and it never consumes candidate snapshots.

## Implementation

- `reference.mjs` exports `createSessionTreeReference()` with root/child allocation, sorted defensive `tree()` records, `list()`, scoped collection methods, leaf-only `dispose()`, and ascending-child depth-first postorder `disposeTree()`. Disposal emits queued cancellations before remaining pending-row cancellations, deduplicates IDs, preserves `Value: ""`, and fences removed IDs.
- `reference.mjs` also exports `mountTreeReferenceCollection(root, runtime, initial, onFailure)`. It independently projects reference snapshots into React 19.3.1 elements, dispatches through the supplied reference runtime, and exposes update, snapshot, DOM, focus/selection, click, input lookup, and unmount methods. It does not add renderer-only methods to the handle; effect and audit inspection stays on the runtime/manager.
- `scripts.mjs` exports three fixed nested witnesses and seeded schedules for 20261030 and 20261031. The defaults produce 30 cases per seed plus the three fixed scripts (63 total). Each action list is capped at 40 actions including setup actions, and generated live session nodes are capped at six. The scripts validate without saving empty drafts or exceeding the collection row cap.

## Verification

The manager and schedule tests were first run before implementation and failed on the missing exports. After implementation, the focused suite passed all 8 tests, including the real-browser reference renderer check. The browser check confirmed React/ReactDOM 19.3.1, input DOM identity, controlled draft update, focus and selection restoration, the absence of a `data-key` dependency, and dispatch/effect output.

# passed: 8 tests, 0 failures; Node v24.22.1, Chromium 153.0.8010.0

## Limits and handoff

This report covers the independent reference and schedule unit/browser tests only. It does not claim candidate-versus-reference parity, Go/WASM comparison, host lifecycle or transport replay, the full session-tree runner, or the inherited multi-root suite. T5 can use `createSessionTreeReference()` as the manager fixture and wrap `mountTreeReferenceCollection(root, runtime, runtime.init(), onFailure)` as the React descriptor; effect/audit observations come from `runtime` or the manager, not the renderer handle. Negative root and child mount actions use `expectError: true`.
