## Implemented checks

`fixture.mjs` runs the Go/WASM candidate and independent pinned React reference in separate documents. For every action, the fixture records an explicit pre-action focus activation (including whether the target was active and its prior/returned selection), then captures the actual document active input, logical focus, and selection immediately after that actor's action. No focus activation occurs after that capture. For a candidate renderer replacement, the reference focus context is captured first, then the candidate replacement is run and captured. Both per-action observations are compared; the candidate replacement target and any focused descendant also have independent expected-selection checks. A missing focus observation is recorded as `null` and fails closed. Selection direction is normalized to `none` only when the selection is collapsed; noncollapsed direction remains exact.

The focus protocol exists because switching between the two real browser documents can itself blur the document that was sampled first. The separately recorded activation makes that context restoration visible. It uses only the prior *observed* active input; if the prior action lost focus, no activation is attempted. Replacement assertions consume the immediate post-replacement capture before any later action. An actual-browser injected `blur()` after a successful replace therefore produces focus parity and `replace.focus-selection` findings, including for caret `0..0`.

The checker fails closed on absent actor/session channels and per-action focus activation or post-action observations, even when both actors omit them. It validates the Go and host trees/list, full per-session state/tree/bindings/messages, audits, renderer lifecycle/errors, snapshot and actual DOM, input order/live values, disabled buttons and paths, shell/view/children ownership, physical parent and retained descendant/sibling input identities, ordered transport events, action message witnesses, postorder disposal, stale callback fencing, and nonempty native segments. Each native frame is independently derived from the reference action/snapshot and checked against the browser frame; `CompareInteraction` runs once for every nonempty per-session segment.

Raw scenarios are written as one JSON shard per script. The mismatch artifact retains the full mismatch array; the tracked summary carries per-shard paths, counts, and SHA-256 values, with global ticks distinguished from candidate and reference session observations. A unit test writes two small scenario shards and 300 mismatches and verifies the complete mismatch count, file contents, and hashes. The first exploratory fixed run had 451 findings but its inline diagnostic preview was capped at 250; that was a reporting defect, not a clean result. The current output keeps all findings in `*-mismatches.json`; `compactMismatches` is only a console-sized preview.
