# T6 — nested demo, browser smoke, runner and CI

## Result

Implemented the nested session-tree demo and its real HTTP browser smoke, documented how to run the demo and the distinction between HTTP lifecycle checks and deterministic manual-transport replay, and added the default runner and CI workflow. The focused demo/browser lane passes. The inherited full suite and T5 replay were not run in this lane.

The demo starts with a DOM family root, a React child, a GoDOM grandchild, and an unrelated GoDOM sibling root. Every Go session receives a separate real HTTP transport lane. Per-node controls add child sessions, select DOM/React/GoDOM renderer replacements, focus collection inputs, choose the next save response, and dispose a subtree. Panels expose the Go tree and snapshots, renderer/focus metadata, postorder cancel bundles, HTTP request/cancel records, and rejected late release results. Disposing a session disconnects its view observer and transport; retired records remain inspectable for cancellation evidence.

The browser smoke uses actual DOM events and the loopback HTTP lab. It proves parent replacement restores logical focus/selection and leaves child shell/input nodes intact; child replacement leaves its grandchild intact; child-subtree disposal cancels descendant HTTP requests in postorder while the family parent and sibling remain live; late releases are rejected; sibling work completes; and a recreated family root has a fresh ID while an old callback is fenced before Go `Complete`.
