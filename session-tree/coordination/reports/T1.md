# T1 — typed session tree manager

## Result

Implemented the additive Go session-tree API in `multisession.Manager`. Root creation keeps its existing signature and allocation behavior. Child creation validates its live parent and depth limit before allocating, and parent/depth metadata is immutable for each session's lifetime. No browser or end-to-end integration pass is claimed here.

## Implementation

- Added exported `SessionInfo` (`SessionID`, `ParentID`, `Depth`), `Disposal` (`SessionID`, `Commands`), and `MaxTreeDepth` (32). Roots have parent 0 and depth 1.
- Added `CreateChild(parent SessionID)`. Unknown, zero, disposed, or depth-32 parents return errors without consuming an ID or changing the tree. Child IDs remain monotonic and capped at the existing JavaScript-safe ID maximum.
- Added `Tree() []SessionInfo`, sorted by session ID. It returns fresh records and a non-nil empty slice when no sessions are live.
- Changed leaf `Dispose` to reject a live non-leaf before draining effects or changing metadata. A leaf is removed from both the session registry and parent tree.
- Added `DisposeTree(id) ([]Disposal, error)`. It validates the root before mutation, builds child-ID-sorted depth-first postorder under the manager lock, returns one cancellation bundle per removed session using the existing queued-cancel then pending-row-order deduplication rule, and removes the whole subtree while still holding that lock. Other branches remain live.

## Tests

Added `manager_tree_test.go` coverage for sorted immutable tree records, non-nil empty results, invalid and dead parents without ID consumption, the exact depth-32 boundary, last-safe-ID allocation and exhaustion, non-leaf `Dispose` atomic rejection (including queued-cancel preservation), deterministic subtree postorder, per-session cancellation bundles, unrelated branch survival, post-disposal fences for all scoped methods, and concurrent child creation/tree reads/overlapping leaf and subtree disposal.

The bridge worker's direct probe independently observed the expected Manager bundles and cancel IDs. Its first browser smoke assertion expected command objects without the zero-value `Value` field; the bridge worker identified this as an assertion-shape issue and is correcting it. That smoke is not recorded as passing here.
